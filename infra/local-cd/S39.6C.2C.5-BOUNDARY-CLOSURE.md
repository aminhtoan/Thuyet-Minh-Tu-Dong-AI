## Remaining actual closure blockers

1. All reachable direct write/export paths do not yet enforce a service/repository
   capability themselves. Existing HTTP envelopes are observed, but the current
   implementation/inventory does not prove exclusive ownership for every direct
   model/fs invocation or future module callback. Do not promote UNKNOWN merely
   because it is imported by an instrumented route.
2. GROUPS default timers are tracked; direct store mutation methods/custom
   schedules lack a complete enforced boundary. They remain UNKNOWN overall.
3. Terminal FENCED shutdown is not implemented safely: server.ts first calls
   registerEntryPoint('shutdown', false), which throws in FENCED; disconnect's
   new tracking would also reject. A separately designed control-only shutdown
   path is required. Do not relax the fence or rely on this exception as safety.
4. Docker identity/token consumer and external-writer coordination are still
   prerequisites for replacement, outside this no-Docker task.

CLI modules outside the root and speculative SDK callback writes were removed
from the list of normal-process application blockers. Production token remains
disabled for the concrete unresolved boundaries above.
