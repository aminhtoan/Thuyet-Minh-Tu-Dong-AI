## Audit and TOCTOU

Upgrade-Local.ps1 and Rollback-Local.ps1 reject service backend before mutations.
Frontend operations use Enter-LocalLock, a FileShare.None operation.lock handle.
Cold deploy rejects an existing project; Compose is not a fencing mechanism.
Release snapshots validate source hashes and image IDs but do not freeze RAM.
Test-DrainConsumer.ps1 verifies the inspected container/image/StartedAt and the
live process's certificate. Between its final response/inspect and a subsequent
Docker stop/recreate, activity, admission, expiry or process identity may change.
Repeated verification reduces the window but cannot remove it.

## Implemented boundary

- Backend-SafetyGate.ps1: two verification stages, required journal sequence,
  always BLOCKED_NO_FENCE; no stop/replacement callback or Docker mutation.
- Test-BackendReplacementGate.ps1: same exclusive operation.lock as upgrade and
  rollback, local Docker check, synthetic-project-only manifest, immutable input
  hashes, fresh live verification at both stages, durable flushed journal writes.
- Incomplete/failed prior journals block later operations for investigation.
  Exact certificate reuse is rejected. This supplements, not replaces, the
  certificate's boot/drain/revision/expiry checks.
- Lock is held through verification and journaling and released in finally.
  It coordinates scripts sharing this state directory, not arbitrary Docker
  clients, other repository copies or other machines.
- Admission is never opened by this gate. The verifier requires it closed.
  External reopening cannot be prevented with current protocol; therefore no
  destructive operation is allowed even after successful verification.

Journal path: ignored .state/backend-gate-journals/<operationId>.json.
Sequence: PREPARED -> FIRST_VERIFIED -> SECOND_VERIFIED -> BLOCKED_NO_FENCE.
Verification/write errors produce FAILED when journaling remains possible;
unwritable or truncated journals never imply success. No automatic recovery.

## Required coordination before enabling replacement

Design a one-way process fencing transition, authenticated and bound to the
deployment operation and full identity. It must atomically close admission,
prevent reopen, verify all counters/observers and DB state and commit terminal
quiescence in the SAME process. No new tracked work may enter after that point;
late activity must invalidate the transition before destructive permission.
The Docker coordinator must consume that operation exactly once, serialize all
authorized controllers, validate exact old container identity at destruction,
and journal candidate identity afterward. A terminal fenced process must not
silently resume business on expiry/crash. Define crash recovery, unauthorized
Docker actor limitations and cross-instance/database ownership before coding.
TTL alone and a local file lock cannot provide this contract. Existing upgrade
and rollback backend guards remain unchanged until separate approval/tests.
