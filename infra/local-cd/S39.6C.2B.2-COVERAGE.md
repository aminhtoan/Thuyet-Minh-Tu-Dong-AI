## Certificate semantics

Status observation reads DB with bounded query times, checks activity revision
before/after observation, and then snapshots same-process observers. READY
requires admissionClosed, a drain operation ID, known coverage/RAM, all operation,
provider, approval, request, store and draft counts zero, connected DB with zero
QUEUED/PROCESSING jobs and zero CLAIMED/UNCERTAIN attempts, plus deployment identity.
No attempt is expired/reset and no provider is canceled to manufacture READY.

Certificate includes certificateId, processBootId, drainOperationId, deployment
identity, activityRevision, coverage profile/status, observedAt/expiresAt (10s)
and DB observation. Only the last issued ID is accepted by that runtime.
Reopening admission, activity starting/settling, identity mismatch, new process,
unknown observer, expiry or a newer certificate invalidates prior acceptance.
New business admissions stay blocked after issuance; health remains available.

This is an observation, not a distributed lock against other DB writers. HOSTNAME
alone is not authoritative Docker identity: B.3 must bind fresh live status to
actual container ID/image/deployment evidence. Do not trust a saved JSON file as
a permanent deploy permission. Backend upgrade scripts are not enabled here.
Internal control remains loopback/authenticated/rate-limited, disabled by default.
