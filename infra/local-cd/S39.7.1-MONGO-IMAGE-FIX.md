# S39.7.1 — MongoDB image prerequisite

Root cause: **CONFIRMED** from the artifact error supplied by the user:
`Error response from daemon: No such image: mongo:8.0.17`.

The runner built Backend/Customer/Admin images, but did not prepare the separate
MongoDB image. Compose specifies mongo:8.0.17 while every up uses --pull never.
Local Docker had this image cached from earlier synthetic tests. A fresh hosted
runner lacked it and was prohibited from pulling it during deployment. This is
an image prerequisite failure, not evidence of MongoDB readiness, volume
permissions, networking or application healthcheck failure.

## Minimal dependency fix

required-images.mjs provides one shared MONGO_IMAGE constant, still mongo:8.0.17.
Before source builds or any Compose project creation, the runner:

1. Inspects the exact image reference.
2. If absent, pulls only mongo:8.0.17 with a bounded timeout.
3. Inspects again and requires a valid image ID before proceeding.
4. Records reference/ID/cache-or-pull result in state and release dependencies.
5. Rechecks that dependency's ID before initial deployment/recovery verification.

No latest fallback, MongoDB version change or removal of --pull never. Pull/error/
timeout/post-pull verification failure exits before deploy. mongo-image.log and
MONGO_IMAGE_FAILED/PIPELINE_FAILED evidence survive; a successful empty-scope
cleanup does not change the pipeline result from FAIL to PASS.

## Diagnostics retained from this task

Failed native commands now emit exit/signal and a redacted output tail directly
into Actions logs, while keeping command log files. Deploy failure captures
Compose ps, Docker/Compose versions, required image availability, owned container
state/health/exit/OOM, user/mounts and relevant source-file permissions. Container
logs are captured BEFORE cleanup. Raw Config.Env is not dumped; credential/Bearer
redaction and foreign-owner rejection are regression tested.

Workflow adds an always-run diagnostics step before the existing ownership-guarded
cleanup. JSON/log artifacts are still exported afterward. No container, network
or volume was changed during local validation of this fix.
