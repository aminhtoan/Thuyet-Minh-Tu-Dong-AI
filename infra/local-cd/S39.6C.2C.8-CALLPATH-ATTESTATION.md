## Live identity consumer and results

Host-side staging/live-attestation.mjs uses the local Docker daemon's inspect
records before and after a scoped client fetch from the exact full container ID.
It verifies image/project/service/StartedAt, maps Backend deployment identity to
inspected hostname, and pins the observed process boot and fence generation.
The extra Node process is just an HTTP client; it does not infer the server RAM.
No container ID or API token printed by Backend is accepted as independent truth.
Token remains inside the synthetic container environment and is not in logs.

| Health/admission | After maintenance close, business API 503 and health 200 |

First enrollment records an observation, not a preexisting trusted boot identity.
Subsequent pinning rejects replay across restart. This consumer does NOT issue a
signed controller attestation or pass an attested identity into the production
control server. It is live independent identity verification, not shutdown
authorization. Root/Docker administrators and malicious image mutation remain
outside application-only protection; no guarantee against those actors is made.
No frontend joins the C.8 network, and no public control port is published.
