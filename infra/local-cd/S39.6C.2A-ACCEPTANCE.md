# S39.6C.2A: frontend-only upgrade/rollback acceptance

Scope: synthetic empty S39.6 environment only. No Backend/MongoDB restart,
recreate, database write, AI call, volume deletion or application source change.
Current active baseline is sha-ddb3ca117aad-82899dbf02a9. Containers/images used
for experiments are retained stopped, never removed. Original frontends are
running again after all tests, each healthy and dual-homed with loopback ports.

## Implementation

- Frontend-Operations.ps1: immutable image/base release verification, actual
  topology and port checks, synthetic DB/jobs and media read-only checks,
  proxy/API/SPA smoke, write-ahead state journal, retained-container recovery.
- Upgrade-Local.ps1: exclusive lock, candidate manifest binding, smoke current
  image first, retain stopped A, create B using image ID, connect both networks,
  smoke candidate and promote. Failed candidate is stopped/retained, A restored
  and smoke-tested. Upgrade command still exits nonzero for a failed candidate.
- Rollback-Local.ps1: frontend-specific journal/identity verification and restore
  known working retained A. Backend rollback remains explicitly BLOCKED.
- Build-SyntheticFrontend.ps1: dedicated good metadata-only and bad Nginx-503
  derivative images, candidate manifests with base ID/backend compatibility.
- Test-FrontendGuardsOffline.ps1: active/unknown/malformed state, business rows,
  Backend operations and interrupted journals all block without mutation.

Original cold-deploy, Build-Release, Compose and Nginx files remain unchanged
by this increment. No automatic deploy workflow is created. Current API
compatibility approval is ONLY for synthetic images derived from the same
baseline: no JS/API contract changes. It is not a general certification for
arbitrary new application versions.

Journal writes use a temporary JSON file followed by rename before advancing
the operation. If interrupted before candidate ID is known, no resources are
deleted and a nonterminal journal blocks later upgrades for inspection. It
does not blindly replay partial operations. Power loss exactly between Docker
mutation and a journal event still requires manual identity reconciliation;
no kill/power-loss injection was performed in this acceptance.

## Limits

Frontend path PASS for this synthetic exercise. Backend upgrade/rollback BLOCKED:
zero jobs cannot prove no process-local drafts, approvals or provider calls.
No bypass exists. Real application API changes, writable candidate operations,
user sessions, asset-cache behavior across browser tabs and arbitrary migrations
are not accepted here. Multi-backend operation and automatic GitHub CD are not
implemented. S39.5 resources were untouched. No advancement to C.2B/D.
